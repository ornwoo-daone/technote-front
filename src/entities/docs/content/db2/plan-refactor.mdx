<Slide kick="문제 1">
## 중복 구현

`planCached`는 메서드로 잘 분리돼 있었지만, 기존 `plan()`은 같은 로직을 **인라인으로 재작성**(적재 루프 + 출력 루프). 고칠 때 두 곳을 따로 손봐야 하는 구조였다.
</Slide>

<Slide kick="문제 2 · 핵심">
## static 가변 맵 = 스레드 안전성 버그

```
// plan() 이 트리를 클래스 static 필드로 재사용
요청 A: tree[1] = [2]   // 넣는 중
요청 B: tree[1] = [9]   // 동시에 덮어씀 (같은 static tree)
→ A의 calcDepth가 B의 엣지까지 계산 → 엉뚱한 plan / NPE
```

<Muted>동시 control 요청 시 데이터가 섞임. CLAUDE.md 리뷰 체크리스트 "static mutable" 위반.</Muted>
</Slide>

<Slide kick="해결">
## 공용 코어 + 지역 컨텍스트

- 행 적재를 `collectRow(rs, ctx)` 로 추출 → 3경로 공유
- `plan()`을 지역 `PlanContext` + 공용 메서드로 교체 → **static 필드 5개 제거**
- 인라인 SQL을 `buildExplainSelectSql()` 로 추출
- 죽은 static 필드(`planInfo`) 제거
</Slide>

<Slide kick="배운 점">
## 공용화 ≠ static 공유

컴팩트함은 **로직(메서드) 재사용**에서 나오지, 데이터를 static으로 두는 데서 나오지 않는다. 상태는 <b>호출 지역(PlanContext)</b>으로 둬야 동시성 안전 + 자동 정리를 얻는다.

<Muted>사이클 간 상태 유지가 필요한 델타 Task는 ExpiringMap instance 필드를 쓰지만, 한 호출로 끝나는 plan 조회는 지역 변수가 정답.</Muted>
</Slide>
