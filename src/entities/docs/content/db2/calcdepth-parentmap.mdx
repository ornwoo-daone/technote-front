<h1>calcDepth 두 가지 방식<br/>tree DFS vs parentMap</h1>
<Lead>plan 트리의 **depth(들여쓰기 단계)** 를 계산하는 두 구현을 비교한다.

<Slide kick="문제의 핵심" err>
## depth와 parent_id의 출처가 다르다

<Lead>서버로 보내는 pack에는 둘 다 들어가는데, **각자 다른 규칙**으로 정해진다.</Lead>

| 필드 | 출처 | 규칙 |
|---|---|---|
| `parent_id` | parentMap | **마지막 행** 승 |
| `depth` (기존) | tree DFS | **방문 순서** 승 — 별개 규칙 |

- 두 규칙이 다이아몬드에서 서로 다른 길을 고르면 → **어긋난 조합**이 서버로 감
- UI는 parent 밑에 자식을 depth만큼 들여쓰는데, `depth(자식) ≠ depth(parent)+1` 이면 **들여쓰기가 밀린 트리**가 그려진다

<Note>그래서 해법의 방향은 "DFS를 고치자"가 아니라 — <b>depth를 parent_id 와 같은 소스에서 뽑자</b>.</Note>
</Slide>

## parentMap — 아래에서 위로 "세기"

<Lead>각 노드에서 **부모를 따라 올라가며** 몇 계단이면 루트인지 센다.</Lead>

  <text x="430" y="45" className="dg-tm">루트 도착!</text>
  <text x="160" y="120" className="dg-goodf" style={{fontFamily:'var(--mono)',fontSize:'14px',fontWeight:700}}>depth(3) = 2계단 = 2</text>

- parentMap은 노드당 부모가 **딱 하나** → 올라가는 길이 유일 → **운이 개입할 자리가 없다**
- `depth(자식) = depth(부모) + 1` 이 **정의에서 저절로** 성립 — parent_id와 어긋나는 게 불가능
</Slide>

<Slide kick="코드 ①">
## 기존 코드 — 라인바이라인

```java
private static void calcDepth(Map<Integer, List<Integer>> tree,
                              int node, int depth,
                              Map<Integer, Integer> depthMap) {
    depthMap.put(node, depth);
    if (tree.containsKey(node)) {
        for (Integer child : tree.get(node)) {
            if (child != -1) {
                calcDepth(tree, child, depth + 1, depthMap);
            }
        }
    }
}
```

- **1행** `tree` = 부모→자식들 지도. 이 지도를 타고 내려간다
- **4행** 지금 서 있는 노드에 depth를 기록 — <b>재방문하면 덮어쓴다</b> (다중 뎁스에서 마지막 방문 승이 되는 이유)
- **5행** 자식이 있는 노드인가?
- **6행** 자식들을 하나씩 순회
- **7행** `-1` 은 "자식 없음" 표기라 건너뜀
- **8행** 자식으로 내려가 재귀, depth는 +1 — <b>순환 간선이면 여기서 무한재귀</b> → StackOverflowError
</Slide>

```java
    depthMap.put(node, depth);
    ...
```

- **4행** 이미 depth가 찍힌 노드로 다시 들어오면 그냥 리턴
- 순환(2→3→2)이든 자기참조(2→2)든 중복 간선이든 — <b>"재방문"이라는 공통 패턴</b>을 입구에서 끊으니 무한재귀는 전부 해결

<Warn>대신 부작용 — 덮어쓰기가 사라지면서 <b>첫 방문 승</b>으로 바뀐다.
다이아몬드에서 depth가 방문 순서(=행 순서=운)에 좌우되는 건 그대로고, parent_id 와 어긋나는 조합이 생긴다. 실측에서 매번 불일치 1건.</Warn>
</Slide>

## parentMap 버전 — 뼈대

```java
static Map<Integer, Integer> calcDepth(Map<Integer, Integer> parentMap) {
    Map<Integer, Integer> depthMap = new HashMap<>();
    for (Integer node : parentMap.keySet()) {
        if (depthMap.containsKey(node)) continue;
        // ... 이 노드에서 부모를 따라 올라간다 (다음 슬라이드)
    }
    return depthMap;
}
```

- **1행** 입력이 `tree`가 아니라 **`parentMap`** — parent_id 와 같은 소스
- **3행** 루트에서 출발하지 않고 **모든 노드를 각자** 처리 → 루트에서 끊긴 고아 노드도 자연히 계산됨 (기존엔 depth 누락 → 별도 보정 필요했음)
- **4행** 이미 계산된 노드는 건너뜀 (캐시)
</Slide>

<Slide kick="코드 ④">
## parentMap 버전 — 올라가기 라인바이라인

```java
List<Integer> path = new ArrayList<>();     // 올라온 길 기록
Set<Integer> onPath = new HashSet<>();      // 이번 등반에서 밟은 노드
int cur = node;
Integer baseDepth = null;
while (true) {
    if (depthMap.containsKey(cur)) {        // 이미 depth 아는 노드 도착
        baseDepth = depthMap.get(cur); break;
    }
    if (!onPath.add(cur)) {                 // 밟았던 노드 또 밟음 = 순환
        baseDepth = 0; break;
    }
    path.add(cur);
    Integer p = parentMap.get(cur);
    if (p == null || p == -1) {             // 부모 없음 = 루트
        baseDepth = -1; break;
    }
    cur = p;                                // 한 계단 위로
}
```

- **1행** 나중에 depth를 되돌려 채우려고 지나온 노드를 순서대로 담는다
- **6~8행** 계산해 둔 노드를 만나면 거기서 멈춤 — 같은 경로를 두 번 안 올라간다 (50만 노드 91ms의 비결)
- **9~11행** `Set.add` 가 false = 이번 등반에서 밟았던 노드 = **순환**. 무한루프 대신 그 지점을 기준 삼고 끊는다
- **13~16행** 부모가 없거나 -1이면 루트 도착. `-1` 로 두면 다음 슬라이드에서 루트가 depth 0이 된다
- **17행** 재귀 없이 `cur` 만 갈아끼움 — 아무리 깊어도 **스택 안전**
</Slide>

<Slide kick="코드 ⑤">
## parentMap 버전 — 내려오며 채우기

```java
for (int i = path.size() - 1; i >= 0; i--) {
    baseDepth = baseDepth + 1;
    depthMap.put(path.get(i), baseDepth);
}
```

- **1행** `path` 는 [출발노드, …, 꼭대기 직전] 순서 — **거꾸로**(꼭대기 쪽부터) 내려온다
- **2행** 기준점에서 한 계단 내려올 때마다 +1. 루트였다면 -1 → 0 → 1 → …
- **3행** 지나온 노드 **전부** 캐시에 저장 — 다음 노드가 이 경로를 만나면 6행에서 바로 멈춘다

<Note>예: 3→2→1 등반이면 path=[3,2], 루트 기준 -1 → 2에 0+1=1, 3에 1+1=2. <b>depth(3)=2, depth(2)=1, depth(1)=0</b> — parent 체인과 정확히 한 계단씩.</Note>
</Slide>

## 한 장 요약

| | tree DFS (기존/가드) | parentMap |
|---|---|---|
| 방향 | 루트에서 **내려가며 뿌림** | 각 노드에서 **올라가며 셈** |
| 다중 뎁스 | 방문 순서 = <B>운</B> | 경로 유일 = <G>결정적</G> |
| parent_id 정합 | 별개 규칙 → 어긋날 수 있음 | <G>같은 소스 → 정의상 항상 정합</G> |
| 고아 노드 | 못 감 (누락) | <G>자연 처리</G> |
| 순환/자기참조 | 가드 있으면 안전 | <G>안전</G> |
| 구현 | 재귀 (스택 한계) | <G>반복문</G> |
| 변경량 | 한 줄 | 함수 교체 + 호출부 1줄 |

<Note><b>결론</b>: 무한재귀만 막으면 되면 가드 한 줄로 충분. 화면 들여쓰기의 <b>정확성까지 보장</b>하려면 depth는 parent_id 와 같은 소스(parentMap)에서 계산해야 한다.</Note>
