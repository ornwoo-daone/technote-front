## TLS 가 뭐길래

전송 계층에 얹혀서 **세 가지를 한꺼번에** 보장한다.

<div className="tscroll">

<Slide kick="기초 ②">
## XOR 이 왜 «약함» 인가

**XOR**(exclusive or, 배타적 논리합)은 두 비트가 다르면 1, 같으면 0 인 연산이다.
같은 키로 두 번 하면 원래대로 돌아온다 — 그래서 암·복호가 같은 코드다.

<span className="enc-src">Cypher.java:111–118</span>

```java
public byte[] hide(byte[] b) {
    for (int i = 0, j = 0; i < b.length; i++, j = (j + 1) % xor_key.length) {
        b[i] ^= xor_key[j];      // xor_key 는 4바이트 (HIDE_KEY, int)
    }
    return b;
}
```

<Warn>**4바이트 키를 계속 반복**해서 덮어씌우는 방식이다. 데이터에 반복되는 패턴이
있으면(JSON 키 이름, 널 바이트 등) 키를 역산할 수 있다. 고전적으로 깨진 방식이라
**«암호화»보다는 «가림»에 가깝다.** 코드의 메서드 이름이 `encrypt` 가 아니라
`hide`(가리다)인 것도 그래서다.</Warn>

<Note>즉 기본 설정(encrypt_level=2)은 **눈에 띄는 평문을 가리는 수준**이지,
도청자에 대한 기밀성을 보장하지 않는다. 보안 요건이 있으면 반드시 3으로 올려야 한다.</Note>
</Slide>

## AES 는 무엇의 약자인가

**AES** = **A**dvanced **E**ncryption **S**tandard (고급 암호화 표준).
2001년 미국 표준으로 채택된, 현재 사실상 전 세계 표준인 **대칭키 블록 암호**다.

<div className="tscroll">

| 용어 | 풀이 |
|---|---|
| **대칭키** symmetric | 암호화·복호화에 **같은 키**를 쓴다. 그래서 키를 안전하게 나눠 갖는 게 관건 |
| **블록 암호** block cipher | 데이터를 **고정 크기 덩어리**(AES는 16바이트)로 잘라 처리한다 |
| **AES-128 / 256** | **키 길이**가 128비트(16바이트) / 256비트(32바이트)라는 뜻. 블록 크기는 둘 다 16바이트로 같다 |
| **ECB** | **E**lectronic **C**ode**B**ook. 블록을 **각각 독립적으로** 암호화하는 가장 단순한 방식 |
| **NoPadding** | 모자란 부분을 채우는 규칙을 라이브러리에 맡기지 않고 직접 처리한다는 뜻 |

</div>

<span className="enc-src">Cypher.java:51</span> — 이 구간이 쓰는 조합이다.

```java
enc = Cipher.getInstance("AES/ECB/NoPadding");
```

<Muted>읽는 법: `알고리즘/운영모드/패딩방식`. 즉 **AES 알고리즘 · ECB 모드 · 패딩 직접 처리**.</Muted>
</Slide>

## cypher_level — AES 키 길이

<span className="enc-src">Configure.java:74, 547–548</span>

```java
public int cypher_level = 128;                       // 기본값
// 로딩 시
this.cypher_level = getInt("cypher_level", 128);
this.cypher_level = this.cypher_level / 128 * 128;   // ← 128 의 배수로 내림
```

<span className="enc-src">Cypher.java:40</span> 에서 이 값이 블록·키 크기가 된다.

```java
this.BLOCK = conf.cypher_level / 8;   // 128→16바이트, 256→32바이트
```

<Note>**정수 나눗셈 때문에 128 의 배수로 내림된다.** `cypher_level=200` 으로 적으면
경고 없이 **128 로 동작**한다. AES-256 을 쓰려면 정확히 `256` 이어야 한다.
설정해 두고 안 먹는 사고가 나기 쉬운 지점이다.</Note>

<div className="tscroll">

| 설정값 | 실제 적용 | 비고 |
|---|---|---|
| 128 (기본) | AES-128 | |
| 256 | AES-256 | JDK 에 따라 JCE Unlimited Strength 정책 필요 |
| 200 | <B>128</B> | 내림 — 의도와 다르게 동작 |
| 0 | 암호화 없음 | `Cypher.BLOCK==0` → 원문 그대로 반환 |

</div>

<Muted>AES-256 설정 문서: `docs.whatap.io/java/aes-256-encryption`</Muted>
</Slide>

## 이 구조에 «없는» 것

암호화가 있다고 보안 요건이 다 충족되는 건 아니다. 앞서 본 TLS 의 세 가지 중
**기밀성만 부분적으로** 있고 나머지는 없다.

<div className="tscroll">

| 항목 | 상태 | 의미 |
|---|---|---|
| 기밀성 | <W>조건부</W> | encrypt_level=3 일 때만. 기본값(2)은 XOR 이라 사실상 없음 |
| 무결성 | <B>없음</B> | HMAC·MAC·체크섬 코드가 없다. 중간에 바꿔치기해도 탐지 못 함 |
| 서버 인증 | <B>없음</B> | 에이전트가 접속한 상대가 진짜 수집서버인지 검증하지 않음 |
| 상호 인증 (mTLS) | <B>없음</B> | 인증서 자체가 없음 |
| 헤더 보호 | <B>없음</B> | PCODE 등 평문 노출 |

</div>

```bash
# 무결성 검증 코드 존재 여부 확인
grep -rn "Hmac|MessageDigest|checksum|CRC32" whatap/dbx/net/
# → 결과 없음
```

<Warn>고객사 보안팀이 “전송 구간 보호”를 요구할 때는 보통 **이 세 가지를 모두** 뜻한다.
애플리케이션 계층 암호화만으로는 답이 되지 않으므로, 망 계층 보호를 함께 제안해야 한다.</Warn>
</Slide>
