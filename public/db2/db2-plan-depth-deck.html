STEP 2 · 보충 ①

왜 tree(부모→자식)가 필요할까?

depth는 위에서 아래로 세야 한다.
맨 위 1번(0칸)에서 시작 → 자식으로 내려가며 +1.

"1번 밑에 누가 있지?"를 알아야 2번으로 내려간다.
"2번 밑엔?"을 알아야 3·4번으로 내려간다.

🔑 내려가려면 부모→자식 방향 지도가 꼭 필요.

✗ parentMap만 있으면
3→2 · 4→2 · 2→1

전부 위로만 가리킨다. "1번 밑에 누가 있나?"를 알 수 없어 내려갈 수 없음.

✓ tree가 있으면
1→[2] · 2→[3,4]

"1번 밑=2번, 2번 밑=3·4번" 바로 앎 → 내려가며 depth 계산 가능.

STEP 2 · 보충 ②

왜 parentMap(자식→부모)가 필요할까?

최종 표에는 parent_id(내 부모가 누구) 컬럼이 있다. 이걸 채우려면 "내 부모 = 몇 번?"을 바로 알아야 한다.

idparent_id
3?

3번 행의 parent_id 칸을 채우는 순간을 생각해보자.

✓ parentMap이 있으면
parentMap[3] = 2

한 번에 "3번 부모=2번" → parent_id에 2 즉시 기입.

✗ tree만 있으면
1→[2] · 2→[3,4]

3번의 부모를 찾으려면 모든 목록을 뒤져 "3이 어느 자식목록에 있나" 검색해야 함. 느리고 번거로움.

한 줄 비유

결국 같은 조직도를 두 방향으로 본 것

tree · 부모→자식
"내 밑에 누구 있어?"

사장부터 아래로 훑으며 "몇 단계 아래인지"(depth)를 센다.

parentMap · 자식→부모
"내 상사가 누구야?"

각 직원에게 바로 상사를 물어 명찰(parent_id)에 적는다.

화살표 한 줄(3→2)을 읽을 때마다 두 지도에 동시에 적는다: tree엔 2 밑에 3 추가, parentMap엔 3의 부모는 2.

STEP 2 · 보충 ③

map 하나면 안 될까? — 컬럼이 2개라서

"내려가려면 tree 하나면 되잖아?" — 맞아. 근데 최종 표엔 계산이 필요한 컬럼이 두 개고, 둘은 서로 반대 방향이야.

depth 컬럼
↓ 위 → 아래

루트부터 내려가며 칸수 세기 → tree(부모→자식)로 계산

parent_id 컬럼
↑ 아래 → 위

각 노드가 "내 부모 몇 번?"에 바로 답 → parentMap(자식→부모)로 채움

tree 하나로 parent_id도 만들 순 있지만, "3의 부모?"를 매번 전체 자식목록을 뒤져야 함. 그래서 미리 뒤집어둔 지도(parentMap)를 같이 들고 다니는 것.

코드에서 데이터가 도는 순서

한 번 적재 → 각 컬럼이 다른 map을 읽는다

1
적재 쓰기 tree쓰기 parentMap
3→2 읽으면 → tree에 "2밑에 3" · parentMap에 "3의 부모 2"

화살표 한 줄로 두 지도에 동시 기록 (한 번의 루프에서)

2
depth 계산 읽기 tree
calcDepth(tree, 1, 0) → depthMap

tree만 타고 내려가며 depth[] 를 만든다 (parentMap 안 씀)

3
표 출력 읽기 parentMap
for (자식→부모 in parentMap) { parent_id = 부모; depth = depthMap[자식] }

parentMap을 돌며 각 노드 행을 찍고, 2단계가 만든 depth를 붙인다

→ tree를 읽는 코드(2단계)와 parentMap을 읽는 코드(3단계)가 서로 달라서 두 map이 다 필요한 것.

두 지도의 최종 내용

원본 화살표 3개(3→2 · 4→2 · 2→1)를 다 읽고 나면, 두 map은 이렇게 채워진다.

tree key=부모 → value=자식들
{
  1 : [2],     // 1 밑에 2
  2 : [3, 4]   // 2 밑에 3,4
}
parentMap key=자식 → value=부모
{
  1 : -1,   // 1은 최상단(부모없음)
  2 : 1,    // 2의 부모 1
  3 : 2,    // 3의 부모 2
  4 : 2     // 4의 부모 2
}

둘 다 같은 트리를 담지만 방향(key↔value)이 반대다. tree는 key=부모, parentMap은 key=자식.

하나하나 어떻게 꺼내 쓰나

key를 넣으면 value가 나온다

calcDepth 가 tree 를 꺼낼 때
tree.get(1)→[2]1 밑엔 2
tree.get(2)→[3,4]2 밑엔 3,4
tree.get(3)→없음멈춤(leaf)

부모 번호를 넣으면 자식목록이 나옴 → 내려가며 depth+1

출력이 parentMap 을 꺼낼 때
parentMap.get(3)→23의 부모=2
parentMap.get(4)→24의 부모=2
parentMap.get(2)→12의 부모=1

자식 번호를 넣으면 부모가 나옴 → parent_id 칸에 기입

→ 같은 트리인데 필요한 방향으로 뽑아 쓴다: 내려갈 땐 tree(부모→자식), 부모 찾을 땐 parentMap(자식→부모).

STEP 3 · 심화

자식이 여러 갈래로 갈라져도 규칙은 똑같다

핵심
같은 부모의 형제들은 전부 같은 depth(=부모+1).
가지가 3개든 4개든 for문이 하나씩 처리한다.
for (child : tree.get(node)) // 자식 몇 개든 반복
  calcDepth(tree, child, depth+1); // 각자 부모+1
calcDepth(1,0) → 1:0
 └ calcDepth(2,1) → 2:1          // 2의 자식 3개 [3,4,5] 를 for로 순회
    ├ calcDepth(3,2) → 3:2       // 자식 없음, 멈춤
    ├ calcDepth(4,2) → 4:2       // 자식 [6] → 한 칸 더 내려감
    │    └ calcDepth(6,3) → 6:3  // 자식 없음, 멈춤
    └ calcDepth(5,2) → 5:2       // 자식 없음, 멈춤
