DB2 · Plan 수집

DB2 Plan은 어떻게 수집되나

실행된 SQL의 컴파일된 plan(section)은 package cache(메모리)에 있고, 그걸 가리키는 executable_id로 꺼내 트리로 만들어 서버에 보낸다.

파이프라인

executable_id → 트리 → 서버

executable_id활성세션에서 획득 (MON_GET_ACTIVITY / PKG_CACHE_STMT)
→
EXPLAIN_FROM_SECTION캐시 섹션을 EXPLAIN_* 테이블에 "펼침"
→
3-way JOIN SELECTSTATEMENT+OPERATOR+STREAM
→
tree→depth→전송calcDepth → 서버
조회 방법

plan 조회 4가지 (소스별)

소스방법키재최적화부하
package cache (메모리)EXPLAIN_FROM_SECTIONexecutable_id❌낮음
catalog (정적, disk)EXPLAIN_FROM_CATALOG패키지 좌표❌낮음
event monitorEXPLAIN_FROM_ACTIVITYappl/uow/act❌캡처 부하
SQL 텍스트EXPLAIN PLAN ... FORSQL 텍스트✅ 풀높음

section explain은 이미 쓰인 plan을 디컴파일이라 가벼움. SQL 텍스트 재-explain이 가장 무겁다.

코드

3경로 + 공용 코어 (Db2Helper)

plan(db, sql, user, pwd)          // SQL 텍스트 → EXPLAIN PLAN
planCached(executableId)          // 캐시 → EXPLAIN_FROM_SECTION
planFromActivity(appl,uow,act)    // 이벤트모니터 → EXPLAIN_FROM_ACTIVITY
// 3경로 공용 코어 (commit df31e9d8c)
collectRow(rs, ctx)               // 한 행 적재
calcDepth(tree, 1, 0, depthMap)   // 트리 깊이 계산
populatePlanLists(L, ctx)         // 9개 배열로 출력
depth

depth 계산 요약

  • DB2 EXPLAIN엔 depth 컬럼이 없어 stream(엣지)으로 트리를 만든 뒤 계산
  • tree(부모→자식들)=depth 계산용, parentMap(자식→부모)=parent_id 채우기용
  • calcDepth: 루트 1=0, 자식마다 +1 (재귀)
  • parent_id vs depth: parent_id=원본 복사(연결), depth=계산(높이) — 다른 값
